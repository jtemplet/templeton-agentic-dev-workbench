# The Idea Wizard

Come up with your very best ideas for improving this project.

## Process

1. **Explore the codebase** — read key files, understand architecture, patterns, and gaps before generating ideas
2. **Generate 30 ideas** — brief one-liner for each, covering a wide range of improvements
3. **Critically evaluate each** — go through every idea systematically, rejecting ones that are not excellent choices for stated reasons, keeping ones that pass scrutiny
4. **Detail the survivors** — for each idea that passed evaluation, explain:
   - What the idea is (concrete, specific, actionable plan with code snippets where relevant)
   - Why it would be a good improvement
   - Possible downsides
   - Confidence that it actually improves the project (0-100%)
5. **Distill to the top 5** — rank by evaluation quality and confidence, present in a clear organized format

## When to Use

- When reviewing a codebase for improvements
- When stuck and need creative solutions
- At the start of a session for fresh perspective on a project

## When NOT to Use

- When the task is already well-defined and scoped
- When you need to ship something specific, not explore possibilities
- On trivially small projects where 30 ideas would be forced

## Key Principles

- **Explore before ideating** — ideas grounded in actual codebase understanding beat generic suggestions
- **Be genuinely critical** — the evaluation phase should reject most ideas; if everything passes, your bar is too low
- **Actionable over aspirational** — each surviving idea should be implementable, not vague
- **Honest confidence scores** — a 40% score with clear reasoning is more useful than inflated 90% scores
